LEARNING PATH

如何真正学会 G1 与调优

先预测，再看日志，最后用单变量 A/B 实验验证。完整路线见 docs/10，调优工作坊见 docs/11。

观察 → 假设 → 实验
01

建立 Region 直觉

先比较 2G/4G 的 Region 大小、数量和 Humongous 阈值，再解释为什么。

HEAP=4g ./scripts/run.sh
02

观察 Young 与分配率

运行 young-gc / allocation-storm，比较 GC 次数、Eden 和 pause 分布。

analyze-gc-log.sh logs/gc-*.log
03

追踪晋升与 Old

执行 promotion，记录 Survivor/Old 变化；再对比 jdk-defaults 的 tenuring。

PROFILE=jdk-defaults ./scripts/run.sh
04

理解 RSet 成本

用 verbose 跑 cross-region，搜索 gc,remset 与 Scanned Cards。

PROFILE=verbose ./scripts/run.sh
05

还原 Mixed 周期

找出 Concurrent Start → Remark → Cleanup → Mixed，标出 STW 与并发阶段。

mixed-gc + docs/09
06

做一次单变量调优

固定 workload，只改 pause target 或 IHOP，比较 P99、GC 次数和 Full GC。

./scripts/tuning-lab.sh allocation-storm
基线→假设→只改一个变量→相同 workload 复测→记录决策

MENTAL MODEL

G1 知识地图

完整参数、日志案例与调优手册见项目 docs/ 目录；G1 全流程与 Bitmap/TAMS/SATB 数据结构见 docs/12。

Region 化堆

2G 堆默认 2048 × 1MB，4G 堆默认 2048 × 2MB。Region 在 Eden / Survivor / Old / Humongous / Free 间转换。

RSet 与写屏障

跨 Region 引用通过 card table、dirty card queue 和 refinement 线程维护；verbose 日志中可查看 gc,remset、Scanned Cards 与 gc,refine,stats。

SATB 并发标记

初始快照标记保证并发标记正确性；TAMS、mark bitmap、Remark 与 Cleanup 构成 space-reclamation 周期。

Humongous

对象大于 region 一半即进入连续 H region。2G/1M region 的阈值约 512KB，4G/2M region 约 1MB。

Mixed GC

并发标记完成后，G1 在年轻代回收中附加低存活率 old region，形成 Pause Young (Mixed) 与 CSet。

Full GC 兜底

晋升失败、H region 碎片或显式 System.gc() 可能退化为全堆压缩。生产环境应定位根因而非调大 IHOP。
